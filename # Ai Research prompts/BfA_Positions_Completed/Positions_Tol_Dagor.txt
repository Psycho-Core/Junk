==============================================================================
TOL DAGOR - POSITIONS AND NUMBERS, BFA 8.3.7 BUILD 35662
==============================================================================
  Map id 1771. Four boss encounters: The Sand Queen 127479, Jes Howlis
  127484, Knight Captain Valyri 127490 and Overseer Korgus 127503, in
  that order in the instance enum. The dungeon is seven stacked
  sublevels and a prison wing: 250 enemy placements and 57 map pins
  in Method Dungeon Tools, and almost no geometry in the server
  script - four position constants in the whole instance, all of them
  barrels.
  Companion file to the tactics document. Every number is tagged with
  the source it came from. Anything I could not read is written
  "unverified".

==============================================================================
0. READ THIS FIRST - WHAT THIS FILE CAN AND CANNOT GIVE
==============================================================================

  Tags:
    [SRV]  a line in the 8.3.7 script: tol_dagor.h,
           instance_tol_dagor.cpp, tol_dagor.cpp, or one of the
           four boss files.
    [DB]   a row in a world SQL update - here the two Tol Dagor
           SmartAI files, 53 rows over 33 creature entries.
    [MDT]  Method Dungeon Tools BattleForAzeroth/TolDagor.lua:
           name, creature id, per-kill force, health, level,
           clone positions, POI pins and the sublevel field.
    [DBM]  DBM-Party-BfA/TolDagor/*.lua: a stopwatch value.
    [LW]   LittleWigs BfA/TolDagor/*.lua: a second value.
    [CALC] arithmetic on the numbers above, inputs always given.
    unverified   no readable source carries the value. Never a
                 guess.

  THE HEADLINE: there is still no creature spawn table for map
  1771. Neither vSLDB file contains a single INSERT INTO creature -
  the 53 rows are smart_scripts and every one of their x, y, z and o
  columns is 0 - and the TrinityCore 9.x and 11.x world updates that
  mention these ids carry creature_template_difficulty and scaling
  rows, not placements. So every boss spawn point, tank point, safe
  spot and pull position is unverified in world coordinates, with
  three kinds of exception, and all three are exact:
    - four barrel constants in boss_knight_captain_valyri.cpp
      that carry x, y and z (3.1), the only z values in the
      instance;
    - 250 MDT clone positions and 57 MDT pins (3.2, 3.4), each
      with a sublevel number and no z at all;
    - the seven-sublevel chain of map-link pins in 2.5, which is
      the walking order, floor by floor.
  Tol Dagor is the first dungeon in this set where the script carries
  no boundary code whatsoever: no ZRange, no CircleBoundary, no
  MoveSmoothPath, no player-kill leash. Nothing in the server pins a
  boss to a room, so sections 4 to 7 can give pulls, timers and
  triggers exactly and geometry only as MDT pins.

2. THE INSTANCE FRAME
==============================================================================

  2.1 MAP 1771. instance_tol_dagor.cpp ends with
      RegisterInstanceScript(instance_tol_dagor, 1771);
  and tol_dagor.h sets DataHeader "TD" and EncounterCount = 4.
  2.2 THE ENUM IS ZERO-BASED, which is the opposite of The Underrot
  and The MOTHERLODE. tol_dagor.h declares:
      DATA_THE_SAND_QUEEN        = 0
      DATA_JES_HOWLIS            = 1
      DATA_KNIGHT_CAPTAIN_VALYRI = 2
      DATA_OVERSEER_KORGUS       = 3
  EncounterCount = 4, so SetBossNumber(4) wants states 0 to 3. Any
  companion that copies the one-based pattern from the other BfA
  instances will be off by one for every door in this dungeon.
  2.3 DOOR DATA IS THE ONLY THING THE INSTANCE SCRIPT DOES. Three
  rows, all DOOR_TYPE_ROOM:
      284467  DATA_THE_SAND_QUEEN         room door
      281030  DATA_KNIGHT_CAPTAIN_VALYRI  room door
      281049  DATA_KNIGHT_CAPTAIN_VALYRI  room door
  LoadDoorData runs from Initialize(). Jes Howlis and Overseer Korgus
  have no door row, so their rooms never lock and no encounter state
  gates anything there. The script has no OnPlayerEnter, no
  OnCreatureCreate, no SetData, no GetData and no Kill call: it
  cannot enforce a leash, a z-band or an exit kill. That is a
  difference from every other dungeon in this set.
  2.4 SEVEN SUBLEVELS. MDT splits the dungeon into sublevels 1 to 7
  and its mapInfo block carries exactly seven viewport overrides,
  one per sublevel. Enemy clones and pin counts per sublevel:

  The boss anchors sit on four different sublevels, one each (3.2),
  so the four fights are on four floors and the route between them
  is a staircase, not a corridor.
  2.5 THE ROUTE, as MDT models it. Twelve map-link pins chain the

4. BOSS 1 - THE SAND QUEEN 127479
==============================================================================

  4.1 SPAWN AND TANK POSITION. Spawn unverified as a world point: no
  creature row with coordinates exists for 127479. MDT anchor
  (438.67, -288.50) on sublevel 1, with no z [MDT]. MDT health
  5,379,465, level 122, per-kill force 0 [MDT].
  TANK: unverified as a coordinate. The script targets the tank for
  one mechanic only (Sand Trap, 4.4a), so nothing pins a tank spot.
  4.2 PHASES: NONE. boss_the_sand_queen.cpp has no HealthBelowPct,
  no SetBossState and no energy check. Three events start in
  EnterCombat and repeat on fixed timers for the whole fight.
  4.3 TIMERS, seconds from pull
      ability                    script [SRV]     LW [LW]  DBM [DBM]
      Sand Trap 257092           8.5, then 14.2      8.5      8.1
      Upheaval 257608            20.5, then 43.4    14.5     20.2
      Sandstorm 257495           30.3, then 34.0    30.0     30.3
  LittleWigs repeats differ from its pull bars: Sand Trap 14.5,
  Upheaval 42.0, Sandstorm 35.0. Its Upheaval cast bar is 4.35 s,
  the only cast time an addon states in this dungeon. DBM's repeat
  bars are 13.2 / 38.5 / 34.0, and its Upheaval timer is keyed to
  257617, the damage spell, not to 257608, the cast (10.5).
  4.4 ASSIGNED-PLAYER MECHANICS AND EXACT TRIGGERS
      a) SAND TRAP 257092 - the victim, at 8.5 s then every 14.2 s. On
      spell hit the script casts 257093 at the target's position and
      summons 131785 Buzzing Drone there with a 5.0 s
      timed-despawn-out-of-combat. The area trigger script for 257093
      casts 257119 on the first unit to enter and then removes itself.
      So the trap is a one-shot ground patch on whoever has aggro.
      b) UPHEAVAL 257608 - SELF-CAST at 20.5 s then every 43.4 s, with a
      target selection 2.0 s later. The selector 257612 makes the boss
      unselectable, then its effect casts 257615 (jump to target) and
      clears the flag. When the 257608 aura is removed the boss casts
      257617 on itself. The target is the random player the selector
      picked, which is the only mechanic here that needs a spread or
      soak decision. See 10.3: the script never sets the pointer the
      damage branch reads.
      c) SANDSTORM 257495 - SELF-CAST at 30.3 s then every 34.0 s. No
      target, no summon, no zone.
      d) SOAK LISTS, KICK ORDER, TANK SWAPS: none. Nothing in the file
      sets an interrupt flag, and no mechanic counts stacks or applies a
      debuff that would force a swap.
  4.5 THE FLOOR PLAN. Sublevel 1 [MDT]. No leash, no z-band, no
  room door until 284467 opens on the encounter state (2.3). The
  graveyard pin for this floor is (462.51, -281.84), 24.8 units from the
  anchor [MDT][CALC].
  4.6 SAFE SPOTS, WITH z. Unverified as points, and there is no z to
  give: the only z values in the instance belong to Valyri's barrel
  array (3.1), 2,200+ units away. What the script does fix is where
  the two ground effects land - Sand Trap on the current victim,
  Upheaval on the player 257612 selects - so the safe spot is
  relative to those two players, not to a coordinate.

10. DISCREPANCIES AND TRAPS
==============================================================================

  10.1 NO SPAWN TABLE. Every boss spawn, tank position, safe spot and
  pull position is unverified in world coordinates. The only z
  values in the instance are the four barrel constants (3.1), and
  they belong to a different map space (10.4).
  10.2 THE ENUM IS ZERO-BASED HERE. EncounterCount 4 with DATA 0 to 3
  (2.2). The Underrot script in this set starts at 1, so copied state
  handling will be off by one for the three doors.
  10.3 UPHEAVAL'S DAMAGE BRANCH CAN NEVER RUN. boss_the_sand_queen
  declares Unit* upheaval_target but never assigns it, never schedules
  EVENT_UPHEAVAL_DAMAGE, and reads upheaval_target->IsAlive() in the
  handler. The 257612 selector casts the jump and clears the
  not-selectable flag, so the fight works, but the damage event the
  script defines is dead code and the pointer is uninitialised.
  10.4 THE BARREL ARRAY IS MARKED WRONG AND IS WRONG. BarrelPositions
  carries //todo correct; entry 0 is 287.86 units from entry 1 while
  1, 2 and 3 form a 9.57 / 11.24 / 15.56 triangle, and all four are
  2,231 to 2,517 units from Valyri's MDT anchor (3.1, 3.3). The
  detonation condition lists 256931 twice, so only three ids are
  tested. The summoned barrel gets TEMPSUMMON_MANUAL_DESPAWN 60000
  but kills itself after 6.0 s, so the 60 s never matters.
  10.5 ADDON SPELLS THE CORE DOES NOT HAVE. LittleWigs and DBM track
  257609 Enrage, 257793 Smoke Powder, 257827 Motivating Cry and
  257956 Motivated; none of the seven script files mention them. DBM
  also keys its Upheaval timer to 257617 (the damage spell) rather
  than 257608 (the cast), which is why its 20.2 s drift from the
  script's 20.5 s is not a mechanic difference.
  10.6 THE CANNON PINS ARE 285 UNITS FROM KORGUS. Massive Blast does
  FindNearestCreature(134025, 50.0), and the two heavy-cannon pins
  sit 285.1 and 287.4 units from the anchor (3.5). Either the pins
  mark something else or the anchor is not the boss room; the script
  cannot tell, and 134025 has no MDT roster record.
  10.7 HOWLIS HAS NO ROOM DOOR AND NO INTERRUPT FLAG. Nor does
  Korgus. Howlis's three casts are all DoCastVictim, including
  Flashing Daggers, and nothing sets an interruptable state even
  though both addons treat Howling Fear as a kick.
  10.8 EXPLOSIVE BURST CAN STOP FOREVER. In boss_overseer_korgus the
  re-schedule for EVENT_EXPLOSIVE_BURST sits inside the if() that
  requires a random target within 50.0 units. One failed selection
  and the event never runs again. Deadeye and Massive Blast schedule
  outside their if(), so they do not share the bug.
  10.9 CROSS IGNITION'S SPOKES ARE ABSOLUTE. The comment says the
  offset should depend on Korgus's orientation (todo), but the six
  256057 casts pass fixed radians: 6.065254, 5.018055, 3.970858,
  2.923661, 0.8292661, 1.876463 - six spokes 60.00 degrees apart on a
  47.51 degree base (3.5).
  10.10 THE INSTANCE SCRIPT HAS NO GEOMETRY. No OnPlayerEnter, no
  ZRange, no boundary, no SetData, no evade kill: only LoadDoorData
  (2.3). A companion cannot copy a leash from this dungeon.
  10.11 FUSELIGHTER'S AURA SCRIPT IS EMPTY. bfa_spell_fuselighter has
  an AfterApply handler with no body and the entry is marked todo
  fix, so the only Fuselighter behaviour in this core is the cast.
  10.12 THE 8.3 EMISSARIES HAVE PINS BUT NO SCRIPT. 161124, 161241,
  161243 and 161244 have MDT records with force 7 and six spire
  pins, and none of the four has a SmartAI row at all (8.2). Their
  only placement in any readable source is the six spire pins in
  3.4, not a creature row.
  10.13 THE MDT COUNTS DO NOT RECONCILE. force sums to 157 and
  force times clones to 1,049 against a stated total of 400 normal
  (8.1). Use the per-record counts, never the total.
  10.14 THE ENUM ORDER HAPPENS TO MATCH THE WALK. Sand Queen,
  Howlis, Valyri, Korgus (2.2) is also sublevel 1, 4, 6, 7 (3.2).
  That is a coincidence worth not relying on: the Underrot enum does
  not follow its route.
  10.15 ONE SPELL IS DECLARED AND NEVER USED. 263052 SPELL_ARMAMENT
  TEST sits in Valyri's enum beside 262327, and no cast, condition or
  handler in the file mentions it. 262327 is the one the quartermaster
  actually casts (6.4d).
