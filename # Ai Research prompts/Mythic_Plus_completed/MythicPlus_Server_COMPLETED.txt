1. PACKETS AND THEIR FIELDS
=====================================================================

KEYSTONE INSERTION (no separate insert opcode exists):
- The fork's full 8.3.7 opcode table (src/server/game/Server/Protocol/Opcodes.h) contains no INSERT_KEYSTONE opcode. Insertion and run start are one client packet: CMSG_START_CHALLENGE_MODE = 0x3554.
- Packet class StartRequest (Server/Packets/ChallengeModePackets.h): Bag (uint8), Slot (uint32), GobGUID (ObjectGuid).
- Registered in Protocol/Opcodes.cpp -> WorldSession::HandleChallengeModeStart (STATUS_LOGGEDIN, PROCESS_THREADUNSAFE).
- Handler (src/server/game/Handlers/ChallengeModeHandler.cpp, HandleChallengeModeStart): resolves the GO with GAMEOBJECT_TYPE_KEYSTONE_RECEPTACLE (type = 49); requires the item to be ITEM_CLASS_REAGENT (= 5) + ITEM_SUBCLASS_KEYSTONE (= 1); reads modifiers ITEM_MODIFIER_CHALLENGE_MAP_CHALLENGE_MODE_ID and ITEM_MODIFIER_CHALLENGE_KEYSTONE_LEVEL from the key; looks up MapChallengeMode entry (must exist, level != 0, entry->MapID == player map); calls InstanceScript::StartChallengeMode(challengeModeLevel); then DestroyItem(Bag, Slot) with source comment "Blizzard do not delete the key at challenge start" (retail-parity deviation, unverified beyond that comment).
- Keystone item = entry 158923 "Mythic Keystone" (wowhead item=158923, added 8.0.1, ilvl 1, "Place within the Font of Power inside the dungeon on Mythic difficulty"). Creation path: item_challenge_key::OnCreate (src/server/scripts/World/challenge_scripts.cpp) -> Player::HasItemCount(158923) ? Player::InitChallengeKey : Player::CreateChallengeKey (declared Player.h).

START:
- SMSG_CHALLENGE_MODE_START = 0x261F, 33 bytes, class ChallengeMode::Start, fields: Affixes (array uint32[3], default {}), MapID (uint32), ChallengeID (int32), StartedChallengeLevel (uint32, ctor default 2), DeathCount (uint32), Energized (bool, ctor default true).
- Sent by InstanceScript::SendChallengeModeStart (Instances/InstanceScript.cpp): MapID = _mapID, ChallengeID = sChallengeModeMgr->GetMapChallengeModeEntry(map)->ID, StartedChallengeLevel = _challengeLevel, Affixes = InstanceScript::_affixes (array uint32[3]; never assigned anywhere in the repo -> starts as 0,0,0).
- Preceding start sequence (InstanceScript::StartChallengeMode): SMSG_CHANGE_PLAYER_DIFFICULTY_RESULT (= 0x273B) Type 5; applies creature scaling via ChallengeModeWorker; teleports party to entrance (world_safe_loc / map entrance trigger); summons GOB_CHALLENGER_DOOR if door position set; ChangePlayerDifficultyResult Type 11 with DifficultyRecID = DIFFICULTY_MYTHIC_KEYSTONE (= 8); SMSG_CHALLENGE_MODE_RESET (= 0x2621, MapID); SMSG_START_TIMER (= 0x25BC) Type TIMER_TYPE_CHALLENGE, TotalTime 10, TimeLeft 10 (10-second countdown); SMSG_CHALLENGE_MODE_START; per-player CastChallengePlayerSpell; after 10 s delay sets _challengeModeStartTime and sends the elapsed timer, opens the door for WEEK.

TIMER:
- No SMSG_CHALLENGE_MODE_UPDATE_TIMER opcode exists in the 35662 table (and github-wide code search for that name returns 0; WowPacketParser has no such parser).
- Fork sends the run timer through the generic elapsed-timer packets: SMSG_START_ELAPSED_TIMER = 0x261C (class WorldPackets::Misc::StartElapsedTimer { TimerID = 1, CurrentDuration }), where TimerID 1 = WORLD_TIMER_TYPE_CHALLENGE_MODE (enum TimerType, SharedDefines.h). SMSG_STOP_ELAPSED_TIMER = 0x261D, SMSG_START_ELAPSED_TIMERS = 0x261E also exist.
- Sent by InstanceScript::SendChallengeModeElapsedTimer at start, on every death, and on player enter mid-run; CurrentDuration from InstanceScript::GetChallengeModeCurrentDuration = (elapsed ms since _challengeModeStartTime / 1000) + 5 * death count (5-second death penalty, in code).
- Whether retail 8.3.7 drives its timer UI with the same generic packet: unverified (the opcode set proves only that no dedicated challenge timer opcode exists in this build's table).

COMPLETION:
- SMSG_CHALLENGE_MODE_COMPLETE = 0x2622, class ChallengeMode::Complete, fields: Duration (int32), MapId (int32), ChallengeId (int32), ChallengeLevel (int32), unk (uint8, default 128).
- Sent by InstanceScript::CompleteChallengeMode via instance->SendToPlayers with Duration = current duration, ChallengeLevel = _challengeLevel + timed upgrades.
- Trigger: InstanceScenario::CompleteScenario (src/server/game/Scenarios/InstanceScenario.cpp) -> if instance->IsChallengeModeStarted() -> instance->CompleteChallengeMode(). (GM path also: src/server/scripts/Commands/cs_instance.cpp.)

DEATH COUNT:
- SMSG_CHALLENGE_MODE_UPDATE_DEATH_COUNT = 0x2620, class ChallengeMode::UpdateDeathCount { DeathCount (uint32) } (a duplicate class ChallengeModeUpdateDeathCount with the same opcode also exists in the header).
- Sent by InstanceScript::SendChallengeModeDeathCount from InstanceScript::OnPlayerDeath (increments _challengeModeDeathCount) and OnPlayerEnter.

RESET / DIFFICULTY / STATS (same opcode family):
- CMSG_RESET_CHALLENGE_MODE = 0x3205 -> HandleResetChallengeMode; CMSG_RESET_CHALLENGE_MODE_CHEAT = 0x3206 -> HandleResetChallengeModeCheat; SMSG_CHALLENGE_MODE_RESET = 0x2621 { MapID } (class ChallengeMode::Reset; also sent during start).
- SMSG_CHANGE_PLAYER_DIFFICULTY_RESULT = 0x273B, class ChangePlayerDifficultyResult { Type (uint8), InstanceDifficultyID (uint32), DifficultyRecID (uint32) }.
- CMSG_CHALLENGE_MODE_REQUEST_MAP_STATS = 0x308F -> HandleChallengeModeRequestMapStats (builds class AllMapStats) and HandleChallengeModeRequestMapStatsOpcode (raw WorldPacket). SMSG_MYTHIC_PLUS_ALL_MAP_STATS = 0x2624, class AllMapStats { vector<ChallengeModeMap> }, ChallengeModeMap = { MapId, BestCompletionMilliseconds, LastCompletionMilliseconds, CompletedChallengeLevel, ChallengeID, BestMedalDate, BestSpecID (vector uint16), Affixes[3] }.
- CMSG_CHALLENGE_MODE_REQUEST_LEADERS = 0x3090 -> HandleRequestLeaders; SMSG_CHALLENGE_MODE_REQUEST_LEADERS_RESULT = 0x2626 { MapID, ChallengeID, LastGuildUpdate, LastRealmUpdate, GuildLeaders, RealmLeaders }, ModeAttempt = { InstanceRealmAddress, AttemptID, CompletionTime, CompletionDate, MedalEarned, Members{ Guid, VirtualRealmAddress, NativeRealmAddress, SpecializationID } }.
- Weekly/record family: SMSG_MYTHIC_PLUS_WEEKLY_REWARD_RESPONSE = 0x2623 (class ChallengeModeMapStatsUpdate { Stats: ChallengeModeMap } - used by WorldSession::SendChallengeModeMapStatsUpdate(keyID)); SMSG_MYTHIC_PLUS_CURRENT_AFFIXES = 0x2625 (opcode present, no packet class / no send site found - unverified); SMSG_MYTHIC_PLUS_NEW_WEEK_RECORD = 0x2628 (class NewPlayerRecord { MapID, CompletionMilliseconds, StartedChallengeLevel } - sender InstanceScript::SendChallengeModeNewPlayerRecord exists but has no callers); SMSG_MYTHIC_PLUS_NEW_SEASON_RECORD = 0x2629 (opcode only). Opcode 0x2627 is absent from the table (unverified).
- CMSG_GET_CHALLENGE_MODE_REWARDS = 0x3683 -> HandleGetChallengeModeRewards - response body is commented out in ChallengeModeHandler.cpp; the class Rewards for SMSG_MYTHIC_PLUS_WEEKLY_REWARD_RESPONSE is commented out in ChallengeModePackets.h.
- CMSG_REQUEST_CHALLENGE_MODE_AFFIXES = 0x3207 -> registered to Handle_NULL (Opcodes.cpp, STATUS_UNHANDLED).
- CMSG_GUILD_CHALLENGE_UPDATE_REQUEST = 0x307C -> HandleGuildChallengeUpdateRequest.

FORCES COUNT:
- No forces-count packet exists: no SMSG_CHALLENGE_MODE_UPDATE_FORCES (or any UPDATE_FORCES) name in the fork's complete 35662 opcode table, github-wide code search returns 0 for both SMSG_CHALLENGE_MODE_UPDATE_FORCES and SMSG_CHALLENGE_MODE_UPDATE_TIMER, and no forces logic exists anywhere in the fork (63 "forces" code hits are all unrelated).
- The fork instead runs the dungeon through an instance scenario (InstanceScenario, ScenarioStep criteria, SQL table instance_scenario_progress); how/if retail 8.3.7 delivers enemy-forces counts to the client (scenario criteria vs world state) is unverified. Client-side events CHALLENGE_MODE_DEATH_COUNT_UPDATED / CHALLENGE_MODE_KEYSTONE_SLOTTED / CHALLENGE_MODE_COMPLETED exist on warcraft.wiki; there is no forces-specific client event in that list.

2. CHALLENGE MODE DATA TABLES
=====================================================================

Client-side (loaded by the fork):
- MapChallengeMode.db2 - loaded as DB2Storage<MapChallengeModeEntry> sMapChallengeModeStore (src/server/game/DataStores/DB2Stores.cpp, "MapChallengeMode.db2"). Fields per DB2Structure.h: Name (localized), ID (uint32), MapID (uint16), Flags (uint8), CriteriaCount[3] (int16). CriteriaCount[3] are used as the three timed brackets: CompleteChallengeMode counts how many of the 3 are > total duration -> 0-3 upgrades. DB2Manager keeps _mapChallengeModeEntrybyMap, _challengeModeMaps, _challengeWeightMaps; GetChallengeModeByMapID(mapID) (DB2Stores.cpp). Existence corroborated outside the fork: TrinityCore master DB2Stores.cpp/HotfixDatabase.cpp and src/tools/map_extractor/loadlib/DBFilesClientList.h all reference MapChallengeMode.db2 (0 github hits for "ChallengeModeMap.db2").
- Game tables: LOAD_GT(sChallengeModeDamage, "ChallengeModeDamage.txt") and LOAD_GT(sChallengeModeHealth, "ChallengeModeHealth.txt") in src/server/game/DataStores/GameTables.cpp (lines 126-127), structs GtChallengeModeDamage / GtChallengeModeHealth. ChallengeModeMgr::GetHealthMultiplier / GetDamageMultiplier read Scalar per challengeLevel and return 100*(Scalar-1) (percent).
- JournalInstance / JournalEncounter / JournalEncounterItem - loot source used by ChallengeModeMgr::Reward (via sDB2Manager lookups).
- Scenario / ScenarioStep - instance scenario completion path (InstanceScenario uses ScenarioStepEntry).
- Upstream TrinityCore master additionally stores ChallengeModeItemBonusOverride (DB2Stores.h) but has no M+ system (see section 4); whether that table exists in 8.3.7: unverified (looks newer-retail).

SQL tables (CharacterDatabase.cpp, fork):
- challenge (ID, GuildID, MapID, RecordTime, Date, ChallengeLevel, TimerLevel, Affixes, ChestID) - INSERT prepared as CHAR_INS_CHALLENGE inside ChallengeModeMgr::SaveChallengeToDB, which has no callers outside ChallengeModeMgr itself (write path appears dead in-repo).
- challenge_member (id, member, specID, ChallengeLevel, Date, ChestID) - CHAR_INS_CHALLENGE_MEMBER (same dead path).
- challenge_oplote_loot (guid, chestListID, date, ChallengeLevel) - weekly chest ("oplote") reservations; CHAR_INS/DEL_CHALLENGE_OPLOTE_LOOT; read via ChallengeModeMgr::HasOploteLoot / GetOploteLoot / GetCAForOplote.
- challenge_key (ID, Level, Affix, Affix1, Affix2, KeyIsCharded [sic], timeReset, InstanceID, guid) - per-character keystone store (CHAR_SEL/UPD/INS/DEL_CHALLENGE_KEY).
- character_completed_challenges (guid, KeyId, MapId, BestCompletion, LastCompletion, Medal, MedalDate) - SELECT/INSERT/UPDATE prepared at CharacterDatabase.cpp lines 154-156, used live by CompleteChallengeMode (best/last/medal updates + SendChallengeModeMapStatsUpdate).
- guild_challenges (GuildId, ChallengeType, ChallengeCount) - guild challenge counters (CHAR_LOAD/INIT/COMPLETE/RESET/REMOVE_GUILD_CHALLENGES).
- item_instance_modifiers (... challengeId, challengeLevel, challengeAffix1, challengeAffix2, challengeAffix3, challengeIsCharged) - persists keystone modifiers on the item.
- instance_scenario_progress - scenario criteria save (InstanceScenario error path).
- character_void_storage also carries the challenge columns (legacy artifact-era columns kept).

- Live run pipeline: start (difficulty switch to DIFFICULTY_MYTHIC_KEYSTONE = 8, entrance teleport, door, 10 s countdown), timer with 5 s death penalty, death count packets, completion packet, upgrade computation from CriteriaCount[3], achievements, journal-loot Reward with item bonus lists, character_completed_challenges + weekly stats push, guild challenge credit, oplote (weekly chest) loot tables.

LACKS / broken or unused (observed in code):
- Affix system not implemented: CMSG_REQUEST_CHALLENGE_MODE_AFFIXES registered Handle_NULL; InstanceScript::_affixes and Group::m_affixes never assigned (start packet sends 0,0,0); all affix effect points in CastChallengeCreatureSpell/CastChallengePlayerSpell hardcoded 0 (slots commented for Skittish/Volcanic/Necrotic/Raging/Bolstering/Sanguine/Tyrannical/Fortified/Bursting/Grievous/Quaking/Explosive); affix aura scripts commented in AddSC_challenge_scripts; SMSG_MYTHIC_PLUS_CURRENT_AFFIXES has no packet class/sender.

- No dedicated timer opcode - generic SMSG_START_ELAPSED_TIMER used instead (retail parity unverified).
- Weekly rewards reply commented out (HandleGetChallengeModeRewards + class Rewards).
- SendChallengeModeNewPlayerRecord has no callers (NEW_WEEK_RECORD never sent by this code path).
- SaveChallengeToDB and the challenge / challenge_member / challenge_oplote_loot INSERT path have no callers outside ChallengeModeMgr itself (dead in-repo).
- SpawnChallengeModeRewardChest is a virtual no-op with no overrides in the repo (no reward chest object spawned; Reward() grants the item directly by toast); SetChallengeModeScenario has no callers; AfterChallengeModeStarted is an empty hook.

- Key is destroyed at start (HandleChallengeModeStart -> DestroyItem), with an in-code comment admitting retail does not do that.
- Comparison note: TrinityCore/TrinityCore master loads sMapChallengeModeStore and sChallengeModeItemBonusOverrideStore but ships none of the ChallengeMode gameplay files (no mgr/handler/packets/scripts) - upstream has the tables, the fork has the mode.
