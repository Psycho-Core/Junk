BATTLE FOR AZEROTH 8.3.7 (BUILD 35662) - ALCHEMY CRAFTING FOR A SERVER-SIDE COMPANION
======================================================================================

Scope: how a computer-controlled character (no client) levels Alchemy on a
TrinityCore-based 8.3.7 server. Every id below was read from a source this
week; anything without a readable source says "unverified" instead of a guess.

7. WHAT THE CORE MUST DO FOR A CRAFT TO SUCCEED
-----------------------------------------------
From TrinityCore master source (Spell.cpp, SpellEffects.cpp, Player.cpp,
NPCHandler.cpp, Trainer.cpp - read this week; line numbers refer to master,
your 8.3.7 fork may differ slightly):
1) The character must know the recipe spell (Player.HasSpell), and the
   spell must pass CheckCast: for tradeskill spells the server checks the
   required skill (failure packet SPELL_FAILED_MIN_SKILL carries the skill
   line id and the required value).
2) Reagents must be in the bags: Spell::TakeReagents (Spell.cpp ~5599)
   destroys SpellInfo Reagent[x] / ReagentCount[x] with DestroyItemCount, and
   it runs BEFORE the effects - the code comment says "we must remove
   reagents before HandleEffects to allow place crafted item in same slot".
   Reagents are gone even if the create fails later.
3) Inventory space: DoCreateItem (SpellEffects.cpp ~1440-1472) stores the
   product; if bags are completely full it sends EQUIP_ERR_INV_FULL /
   EQUIP_ERR_ITEM_MAX_COUNT and RETURNS - no product, and UpdateCraftSkill
   is never called (reagents already lost). A bot must guarantee a free slot
   for the product count before casting.
4) The product is created by SPELL_EFFECT_CREATE_ITEM (EffectCreateItem ->
   DoCreateItem with ItemContext::Trade_Skill for spells with
   SPELL_ATTR0_IS_TRADESKILL); signature items get "Crafted by" creator.
   Sampled alchemy spells are 2-second casts (2330, 252382, 28555, 53837,
   80494, 188299 all "Cast time: 2 seconds"); the MoP Classic page of 114752
   shows 1.5 s (era flag in section 9).
5) Skill-up: only after at least one item was created, Player::
   UpdateCraftSkill(spellInfo) runs (Player.cpp ~5410): it skips spells with
   SPELL_ATTR1_NO_SKILL_INCREASE; finds the SkillLineAbility entry whose
   SkillupSkillLineID is the skill being raised; gain per craft =
   NumSkillUps x CONFIG_SKILL_GAIN_CRAFTING, rolled through
   UpdateSkillPro with SkillGainChance(skill, TrivialSkillLineRankHigh,
   midpoint, TrivialSkillLineRankLow) - those ranks are the orange/yellow/
   green/grey numbers the client shows as recipe colours. Grey recipes never
   gain (wiki colour table: orange always, yellow probably, green rarely,
   grey never).
6) DISCOVERY: inside UpdateCraftSkill, if the spell's Mechanic is
   MECHANIC_DISCOVERY the server rolls GetSkillDiscoverySpell(line, spellId,
   player) and LearnSpell(result) - the comment in the code is literally
   "Alchemy Discoveries here". Wowhead flags sampled Outland/Northrend/Cata/
   MoP recipes with "Mechanic: Discovery" (28555, 53837, 80494, 114752).
   Discoveries are how Pandaria levels (section 3.5) and how Legion Rank 3
   recipes appear.
7) Spell focus: the core supports focus objects (GameObjectFocusCheck, Spell
   .cpp ~2321; failure arg = focus object id ~4472) and aura-granted focus
   (SPELL_AURA_PROVIDE_SPELL_FOCUS ~6063). No sampled alchemy spell requires
   a focus, and the official wiki text says "Most alchemical brews can be
   created anywhere, as long as you have the appropriate reagents". Legion's
   188299 reagent box even says "No longer requires the Dalaran Alchemy
   Station". Station/focus needs for your fork: none found, treat as
   unverified only if a recipe fails with a focus error.
8) Learning a recipe from a trainer: the client sends CMSG_TRAINER_BUY_SPELL
   (NPCHandler.cpp HandleTrainerBuySpellOpcode). The server requires: the NPC
   has UNIT_NPC_FLAG_TRAINER and is in interaction range, an OPEN trainer
   interaction (PlayerTalkClass InteractionData must be "IsInteractingWith
   ... PlayerInteractionType::Trainer" and the matching TrainerID - the
   window is opened by the trainer-list request first), then
   Trainer::TeachSpell runs the gates of section 5 (known/race/skill/level/
   prerequisite spells/free primary profession point), takes the money with
   reputation discount, and then either CastSpell(self, spell, triggered) if
   the trainer spell is "castable" (Trainer::CanTeachSpell passes and the
   spell is IsCastable) or LearnSpell directly.
9) Cooldowns: some transmutes share a cooldown that resets daily at midnight
   server time since patch 4.0.1 (wiki); some transmutes need an alchemist
   stone carried or equipped (wiki); Cataclysm gem transmutes need a
   Philosopher's Stone-type trinket in the INVENTORY (guide; not equipped).
   Alchemy-specific daily procs (e.g. BfA Transmute: Expulsom 251832 listed
   in wowhead's BfA guide) follow the spell cooldown the server has in data -
   per-spell cooldowns unverified here.
10) Passive perks that change numbers, not success: Mixology (longer/
    stronger elixirs/flasks, on 2259 and each expansion learn spell);
    Goblin racial Better Living Through Chemistry 69045 - effect "Mod Skill
    (Alchemy 171) Value 5" (+5 per spell page and wiki; all eight
    wow-professions guides say +15 - section 9).

8. WHAT A SERVER-SIDE CHARACTER (NO CLIENT) CANNOT DO
-----------------------------------------------------
- Cannot see the profession window: recipe lists, spell ids, reagent counts
  and the orange/yellow/green/grey colours live in client UI fed by server
  data (SkillLineAbility ranks). The bot must read recipes/ids from the DB
  or this file and compute colours itself, or ignore them.
- Cannot learn a spell "by opening the trainer": it must script the trainer
  interaction sequence (open trainer list, then CMSG_TRAINER_BUY_SPELL with
  NPC guid + trainer id + spell id). Buying without an open interaction is
  rejected (NPCHandler interaction guard).
- Cannot run quests the normal way: Legion's path needs quest 39325 plus a
  ~26-quest chain (39346 flask unlock at level 45), Draenor needs the
  treatise chain (34019/33410) or garrison work order, BfA Rank 2+ recipes
  come from trainer skill gates and the Nazjatar recipes need the Nazjatar
  intro - all require quest-system scripting (or directly LearnSpell
  server-side, which changes what "earned" means but works).
- Cannot reliably farm reputation- or dungeon-gated recipes: BfA Rank 3s
  need Revered reputation with six factions (named vendors in section 3.8);
  Legion Rank 2 recipe items drop from Mythic/Heroic dungeons (Blackrook
  Hold, Maw of Souls, Halls of Valor, Vault of the Wardens, Eye of Azshara,
  Court of Stars, Arcway, Neltharion's Lair) - dungeon content a headless
  character cannot enter without dungeon automation.
- Cannot predict randomness: yellow/green craft rolls, discovery rolls
  (Pandaria's whole route and Legion Rank 3s), and Rank 3 bonus procs are
  server RNG; a fixed craft count may stop short (each guide warns about
  extras).
- Cannot buy out of the shopping list without AH/mail flows: the guides'
  cheapest routes assume Auction House herb purchases; limited-supply vendor
  recipes (TBC 22907/22911) need vendor-purchase packets plus wait timers
  (18-20 min / 5-10 min respawns).
- Cannot bypass cooldowns: shared transmute cooldown (daily midnight
  server-time reset), spell cooldowns, and Draenor's recipe buy rotation
  ("wait at least 4 days" for more flask recipes).
- Can fail with a full bag and silently lose reagents (section 7.3) - the
  client player would see an error; a bot must pre-check bag space.
- Easy trap: TWO Linzy Blackbolts exist (Northrend Dalaran 28703 vs Legion
  Dalaran 92456); the wrong one does not teach Northrend Alchemy.
- Reputation discounts (Trainer.cpp) only apply once the faction reputation
  is in the server data - a fresh bot pays full price.
