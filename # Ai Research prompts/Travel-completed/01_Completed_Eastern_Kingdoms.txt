WHAT IS VERIFIED AND WHAT IS NOT
  Positions are TaxiNodes.Pos from Map 0 of the 8.3.7.35662 export: they are where the taxi mount sits, which is also where the
  flight master has to be spawned for the node to open. They are not a player-facing walk-up spot, and no file in this repo gives
  one, so every "walk-to position" line says unverified rather than a guessed offset.
  Creature entries: where the underlying research pass had a Wowhead lookup that returned the exact flight-master name for 8.3.7,
  that entry is used. Every other entry was matched on the exact NPC name against creature_template exports (the TDB update pack
  for 4.3.4 and the 8.x creature_template dump that ship in the same server repository). 25 of the 26 Eastern Kingdoms names that
  the Wowhead pass had already verified come back with the identical entry from those exports, which is the cross-check for the
  rest; the one that differs is Cedrik Prose (node 16), where the dump has row 2835 and the 8.3.7 lookup returned 144055, so the
  printed 144055 is the Wowhead row. James Stillair (node 195) has two rows, 43045 and 52753, and the 8.3.7 lookup names 52753.
  Where more than one creature_template row carries the same name and nothing in these sources decides between them, the entry is
  written unverified with every candidate id instead of a pick. That affects these masters:
  Darla Harris, Thysta, Swift Seahorse, Robert Rhodes, Colin Swifthammer, Raskha and Gorthul.
  The three pairs of faction twins - Booty Bay (18/19), Light's Hope Chapel (67/68) and Thorium Point (74/75) - carry a different
  master per faction: Gringer against Gyll, Georgia against Khaelyn Steelwing, Grisha against Lanie Reed. A by-name lookup that
  ignores the faction letter returns the Alliance master for both nodes of a pair.
  In Vashj'ir the two nodes of each ship/beach pair (605/611, 606/607, 608/609, 610/612) are the on-deck/on-land point and the
  in-water boarding point of one location, and the wiki names both variants. Which node of a pair gets the Swift Seahorse is decided
  here by the z of the roost (the in-water node is the lower one); the master names are verified, the pairing of node to master
  inside each pair is that inference and is noted on the line.
  Travel time is derived, not read: the tables carry TaxiPath.Cost in copper and a TaxiPathNode.Delay that is 0 on 86,384 of 86,627
  rows, so neither is a clock. Minutes here are yards / 1920, i.e. 32 yards per second. Every pair of Eastern Kingdoms nodes in the
  export exists in both directions, so no leg in this file is one-way.
  Gate evidence: the 110 Eastern Kingdoms nodes use exactly these ConditionIDs - none, 20068, 923, 924, 7305, 5793, 10723, 10950,
  10988, 46758, 46791, 62731, 64389 - and every one of those rows decodes to a race mask, a class mask, a MinLevel/MaxLevel or a
  PrevQuest, which are the fields these PlayerCondition rows carry. There is no achievement field and no reputation field in that
  decode, so no Eastern Kingdoms taxi node can be gated on an achievement; the only level value in the set is the deliberate 999
  on Southshore. Level and quest requirements that gate the flight master NPC itself
  rather than the taxi node are marked as wiki notes where the wiki states one, and are otherwise not in these tables.
  Sources: TaxiNodes and TaxiPath exports for build 8.3.7.35662, the PlayerCondition decode of every ConditionID listed above, the
  Warcraft Wiki flight-master tables by location and zone, and the creature_template exports named above. Everything read from a
  source is printed; nothing was estimated.
