==============================================================================
THE MOTHERLODE!! - POSITIONS AND NUMBERS, BFA 8.3.7 BUILD 35662
==============================================================================
 Map id 1594. Four encounters: Coin-Operated Crowd Pummeler 129214,
 Azerokk 129227, Rixxa Fluxflame 129231, Mogul Razdunk 129232.
 Companion file to the tactics document. Every number is tagged with
 the source it came from. Anything I could not read is written
 "unverified".

0. READ THIS FIRST - WHAT THIS FILE CAN AND CANNOT GIVE

  Tags:
    [DB]   a row in a world SQL: a smart_scripts row, a
           creature_template row, or a game object id.
    [SRV]  a line in the 8.3.7 script: the_motherlode.h,
           instance_the_motherlode.cpp, the_motherlode.cpp, or one of
           the four boss files.
    [MDT]  Method Dungeon Tools BattleForAzeroth/TheMotherlode.lua:
           name, creature id, per-kill force, health, level, points.
    [DBM]  DBM-Party-BfA/TheMotherload/*.lua: a stopwatch value.
    [LW]   LittleWigs BfA/TheMotherlode/*.lua: a second stopwatch
           value.
    [CALC] arithmetic on the numbers above, inputs always given.
    unverified   no readable source carries the value. Never a guess.

  THE HEADLINE, because it shapes the whole file: there is NO public
  creature spawn table for map 1594, and unlike the six dungeons before
  this one there is not even a SmartAI file to fall back on. TrinityCore
  11.x and 9.x were checked for creature rows and returned only
  creature_template_difficulty; vSLDB carries four Motherlode SQL files
  and all four are loot or journal data. So in this file:
    - boss spawns, tank positions and safe spots are unverified, except
      the seven script constants in section 3, which are exact;
    - pull positions with z are unverified; MDT's layout is in 8.3 as
      RELATIVE map-space geometry only, because MDT stores positions in
      its own map space and no conversion to world coordinates was
      readable;
    - line of sight is unverified. This instance has no door objects in
      its instance script at all (2.3), so there is nothing to anchor
      LOS to;
    - timers and assignments are fully sourced, from the scripts and the
      two addons.

  3.1 THE SEVEN CONSTANTS, ALL IN boss_azerokk.cpp [SRV]. Names are
      the C++ symbols, arrays expanded one row per element.
      name                x          y          z        o
      centerPos           1215.50   -3325.10    57.33   0.00
      earthragerPos[0]    1233.36   -3321.13    57.50   0.00
      earthragerPos[1]    1216.14   -3340.71    55.34   0.00
      earthragerPos[2]    1199.50   -3330.84    55.80   0.00
      earthragerPos[3]    1202.84   -3315.90    55.58   0.00
      frackingPos[0]      1180.16   -3300.33    56.83   0.00
      frackingPos[1]      1181.85   -3301.90    56.79   0.00
      All seven are Position literals with three components, so every
      orientation is the default 0.
  3.2 WHAT EACH ONE IS FOR.
      a) centerPos is commented //40y and is NEVER READ by any code
         path in the file. It is a note from the author that the arena
         is 40 yd across, and it is the only statement anywhere about
         its size.
      b) earthragerPos[4] is used verbatim by SpawnAdd(), once per
         index in a loop of four, with TEMPSUMMON_DEAD_DESPAWN. These
         are real spawn points, not random offsets.
      c) frackingPos[2] is used the same way for the two totems, with
         TEMPSUMMON_MANUAL_DESPAWN.
      d) Measured from centerPos [CALC]: the four earthragers are
         18.30, 15.75, 17.07 and 15.75 yd away; the two totems are
         43.16 and 40.88 yd away. So the adds stand INSIDE the 40 yd
         arena and the totems stand ON or just OUTSIDE its edge. That
         is the one positional statement this file can make about the
         Azerokk room, and it comes from two exact numbers.

  3.3 WHAT IS NOT A COORDINATE. There is no spawn row for any of the
      four bosses, no tank point, no safe spot, no waypoint path and no
      area trigger. The only other positional constant in the four boss
      files is a distance: Azerokk evades when he is more than 25.0 yd
      from his home position (CheckHomeDistToEvade(diff, 25.0f)), which
      pins the fight to a 25 yd leash around where he was placed [SRV].

  5.6 SAFE SPOTS, WITH z

      - where Azerokk himself stands is unverified, and so is every

      Three roster facts worth naming. The four bosses carry count 0,
      so they contribute nothing to the force budget and their health
      is a nameplate figure, not force. Mechanized Peacekeeper is two
      records, 136139 and 130485, for the same creature: 2 clones plus
      4 patrol points in one and 12 clones in the other, which is why
      a Peacekeeper count cannot be read off a single row. And only
      seven records patrol at all: Peacekeeper, War Machine,
      Mastermind, Alchemist, Hired Assassin, Stonefury, Earthshaper.

  8.2 THERE IS NO TRASH SCRIPT TO QUOTE. This is the first dungeon in
      this set where section 8 has no table of rows: the repository has
      no C++ AI for any non-boss creature on map 1594 beyond the mine
      cart, and the vSLDB Motherlode SQL files are loot and journal
      data. So the trash mechanics below come from the addons only, and
      every one of them is a retail statement, not a statement about
      this core.

  8.3 THE PULL LAYOUT, AND WHY IT IS NOT IN THIS FILE AS COORDINATES.
      MDT stores every clone in its own map space, which has no z, and
      no map-space to world conversion was readable. So every pull
      position with z is unverified.
      What MDT does give: the four boss anchors, in MDT units, which
      fix the walking order of the dungeon (it matches the encounter
      ids 0 to 3):
        Coin-Operated Crowd Pummeler  (383.5, -269.4)   encounter 0
        Azerokk                       (252.2, -149.5)   encounter 1
        Rixxa Fluxflame               (466.8, -112.2)   encounter 2
        Mogul Razdunk                 (578.2, -210.9)   encounter 3
      Straight-line spacing between consecutive anchors [CALC]: 177.8,
      217.9 and 148.9 MDT units. Those are chord lengths in map space,
      not path lengths. The longest is the second leg, Azerokk to
      Rixxa, and Azerokk is the only boss whose room has a stated size
      (40 yd, 3.2a) - so the one room this file can measure is also the
      one the route spends the most distance leaving.
      The counts per enemy in 8.1 are the pull sizes to plan for. There
      is no way to say where any of them stands.

  8.4 INTERRUPT DUTY, AS THE ADDONS SEE IT [LW][DBM]
      DBM builds interrupt warnings for six trash casts and LittleWigs
      logs the same six. The priority words are DBM's own comments:
        263202  Rock Lance - no cooldown, spell lock only, spammed
        280604  Iced Spritzer - high priority
        268702  Furious Quake - high priority
        269302  Toxic Blades
        268797  Transmute Enemy to Goo - high priority
        263215  Tectonic Barrier - off by default, because
                  Furious Quake is the priority interrupt
      Tectonic Barrier also carries a separate magic-dispel warning
      (263215, MagicDispeller), so DBM expects it to be dispelled
      rather than interrupted. Its file adds Activate Mech 267433 as a
      heroic-and-mythic cast and five more interrupts commented out
      (268709, 268129, 263103, 263066, 262540). Nothing in the
      repository can confirm any of these ids on this core, so read 8.4
      as a list of what the addons watch, not as a script.

10. DISCREPANCIES AND TRAPS
==============================================================================

  10.1 NO SPAWN TABLE AND NO TRASH SCRIPT. Every boss spawn, tank
       position and safe spot in this file is unverified for that
       reason, every pull position with z is unverified with it, and
       section 8 has no DB rows to quote at all.
  10.2 THE ENCOUNTER DATA IS ZERO-BASED (2.2). A DB row that opens
       encounter 1 opens Azerokk, not the first boss.
  10.3 THE INSTANCE SCRIPT HAS NO DOORS AND SAYS SO. It opens with
       `//Missing scripts`, registers four GUIDs and nothing else. Any
       tactic that assumes a door closes behind the group is assuming
       something this core does not implement.
  10.4 FOUR PUMMELER SPELLS ARE DECLARED AND NEVER USED: 271785 Throw
       Coins, 256137 Timed Detonation, 255996 Punt and 256163 Blazing
       Azerite. DBM still bars Throw Coins (12.2 s) and Blazing
       Azerite, so two retail mechanics are missing here.
  10.5 AZEROKK'S FIXATE CALL PASSES A SELECTOR ENUM WHERE A UNIT
       BELONGS: me->CastSpell(SELECT_TARGET_RANDOM, SPELL_RAGING_GAZE
       _SELECTOR). SELECT_TARGET_RANDOM is a targeting constant, not a
       creature, so the selector is never applied to a chosen player.
  10.6 EVENT_FIXATE IS NEVER RE-ARMED. In bfa_npc_earthrager the
       Fixate case casts and breaks without scheduling itself again, so
       the gaze happens once per Earthrager, 2.0 s after it enters
       combat, and never again.
  10.7 THE AZERITE INFUSION FILTER REMOVES FROM THE LIST IT IS
       ITERATING: for (auto toDelete : clist) if (...) clist.remove(
       toDelete). That is undefined behaviour, and it is also why 5.4d
       says the stun filter does not work as written.
  10.8 THE FRACKING TOTEM MAKES TWO UNCHECKED DEREFERENCES. It declares
       Player* invoker; with no initialiser; only the summon branch
       assigns it (GetSummoner()->ToPlayer(), which is null if the
       summoner is not a player), and the guard `if (!invoker) return;`
       then tests an indeterminate value on every other path. Past that
       guard it calls rager->GetEntry() on invoker->GetSelectedUnit()
       with no null check, so a click with nothing selected dereferences
       null. The stun itself is also one-shot: canStun latches on the
       first click and Reset is the only thing that clears it.
  10.9 RIXXA'S Reset SETS HER BOSS STATE TO FAIL, and her Chemical Burn
       event casts BOTH 259853 and 259856 at the same victim in one
       event before delaying everything else 5.0 s.
 10.10 RAZDUNK'S JustDied CALLS _JustDied() AND BossAI::JustDied().
       One of the two is redundant, and both run on the same death.
 10.11 THE ADDONS BAR SPELLS THIS CORE DOES NOT HAVE: 275992 and
       270042 on Rixxa, 259940 and 260813 as alternate ids for spells
       the script calls 260669 and 260838, and LittleWigs' 1217294 key
       for Shocking Claw, plus 271784, 256493 and 271456 standing in
       for 271785, 256163 and 260202. Read every addon number here as
       retail.
 10.12 A CROSS-DUNGEON COINCIDENCE WORTH KNOWING: Rixxa's MDT health,
       5,379,465, is exactly the MDT health of Siege of Boralus's Hadal
       Darkfathom. If you see that number in a loot or scaling table it
       is not evidence that the two share data.
 10.13 RAZDUNK'S DRILL AURA IS APPLIED AND REMOVED ON DIFFERENT UNITS.
       Drill Smash casts 260189 with DoCastVictim, but Alpha Cannon
       calls me->RemoveAurasDueToSpell(260189) on the boss. If the
       spell's target entry is not 'caster', the aura sits on the tank
       while the removal looks in the wrong place; if it is 'caster',
       the aura sits on the boss and the victim cast does nothing. The
       target entry is not in any file here (10.x is where this file
       would have to stop).
