Added: patch 8.0.1 (2018-07-17), Battle for Azeroth

READ THIS FIRST - the map exists, the arena does not.
This BfA core declares the type and queues it, but has no zone
implementation for it:
  - SharedDefines.h declares BATTLEGROUND_HOOK_POINT = 897
  - BattlegroundMgr::CreateNewBattleground has cases for AV, WS, AB,
    NA, BE, EY, RL, SA, DS, RV, IC, TP, BFG, TTP, TVA, NNA, AF,
    BEG, BRH and MUGAMBALA, and no case for HOOK_POINT, so the
    type falls through to the default branch, which returns
    nullptr and creates no instance
  - there is no Hook Point zone file in
    src/server/game/Battlegrounds/Zones, under any spelling
So on a private server built from this core the arena cannot be
created at all. Everything below marked "server" therefore comes
from the world safe locations only; nothing is spawned.

=== 2. GATES ===

None. This core spawns no gates on map 1825 because it has no
Hook Point zone class, and there is no other file that places
objects on this map.

What would be needed to make the arena work on a private server:
  a zone class registered in BattlegroundMgr::CreateNewBattleground
  for BATTLEGROUND_HOOK_POINT, plus the door and orb positions.
None of that data exists in any readable source I found, so gate
count, entries and coordinates are all unverified.

=== 3. PILLARS AND LINE OF SIGHT OBJECTS ===

Two pillars in the middle, one fenced side.

  "It is a squared off area with two pillars in the middle area.
   One side is covered by fences allowing for line-of-sight, with
   the middle and both ends open. Overall this map is of medium
   size, allowing for players to cast spells across a majority of
   the map at max range, and allows players to not need to travel
   considerable distances to get out of LOS."
   (Liquipedia)

  "it has an asymmetrical shape, with pillars slanted and a tall
   and long wooden fence on one side. The starting position is
   not facing each other, but is asymmetrically placed in front
   of the pillar."   (NamuWiki arena page)

The two descriptions agree on two pillars, one long fenced side,
and an open middle. They agree on asymmetry too, and the server
data backs it: the starts are 25.06 and 21.88 degrees off the
line between them, and Game On sits 22.66 units off the midpoint
rather than between the teams.

Pillar count: 2, slanted rather than square to the arena
Pillar positions: unverified
Fence side: unverified which side, other than "one side"
Nothing is spawned in server data, so there is no third source to
arbitrate. This section rests entirely on the two wiki pages.

=== 5. USUAL FIRST POSITIONS BY ROLE ===

Read with caution: with no zone file and no spawn data, the
following is reasoned from the two published descriptions, not
from coordinates.

Two pillars in the middle and open ends mean the centre is the
only cover, and the fenced side is the only wall.

Melee DPS:
  Race for the pillars. There are only two, and both sit in the
  middle area, so losing that race means fighting in the open
  Approach along the diagonal, because the starts face 25.06 and
  21.88 degrees off the line between them

Ranged DPS:
  The map is medium sized and open at both ends, so max-range
  casting across the middle is possible. Do not stand in the
  open middle against a melee cleave
  Use the fenced side as a wall when you need LoS, and the open
  ends when you need space

Healers:
  Play the edge of the fenced side, where there is wall plus a
  pillar within a short walk
  Do not hold the open end: there is nothing to hide behind
  there, and the enemy spawn is close to one end

General opener notes:
  Both teams are 56.86 from the midpoint, so first contact is
  close to simultaneous
  The start line is diagonal (86.35 by 73.99), so the two teams
  do not approach along one clean axis
  Game On is 22.66 off the midpoint, which is consistent with an
  asymmetric layout rather than a mirrored one

=== 7. MATCH FLOW NOTES ===

The type is queued but cannot be created:
  battleground_template has row 897 with Weight 1, so the queue
  will select it
  BattlegroundMgr::CreateNewBattleground has no HOOK_POINT case and
  reaches "default: return nullptr;"
So a queue pop for this arena on a server built from this core
fails to produce an instance. That is the single most important
line in this file for anyone running the arena set.

Dampening, Arena Preparation and the arena countdown would apply
if the instance were created; they are inherited from Arena, not
per-map. Nothing on this map overrides them because nothing on
this map exists in the core.
