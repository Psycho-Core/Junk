1. WHO THE ENEMY TEAM IS
   On Normal, Heroic and Mythic the 3-player group faces a team of 3
   Advanced NPC opponents from the opposite faction, racing to the
   required Azerite total (warcraft.wiki.gg). On PvP the opponents are
   3 human players, not NPCs (warcraft.wiki.gg; moudi guide: "PvP mode
   (against 3 other players)").
   The NPC groups are mirrored between the factions - "a pirate group
   on each side, gnomes on one side and goblins on the other, Horde
   pyromancers against Alliance cryomancers" (wiki). All of them rest
   in the open world between runs: Alliance teams at Tradewinds Market
   in Boralus, Horde teams in Dazar'alor (wiki).
   Alliance teams (8, wiki names):
     Briona's Buccaneers - Briona the Bloodthirsty, Varigg,
       "Stabby" Lottie (dwarven/gnomish pirates)
     Auric's Angels - Frostfencer Seraphi, Squallshaper Bryson,
       Squallshaper Auran (hydromancers)

       Archmage Tamuura (draenei)
     Razak's Roughriders - Razak Ironsides, Dizzy Dina,

2. HOW THE ENEMY TEAM PICKS TARGETS
   What is sourced:
   - It is a race: first side to the Azerite total wins; combat is
     optional skirmishing along the way, fog of war hides both teams
     (warcraft.wiki.gg Gameplay).
   - AI teams "mimic player behavior", "prioritize Azerite nodes and
     strategically engage players", adapt to player actions, and grow
     more aggressive "if players focus on combat rather than
     gathering"; behavior is "influenced by several factors, including
     the number of players in the expedition and the current Azerite
     score" (superlativelyrude.com guide, Sep 2026).
   - Progress is delivered in announced stages: stage 2 raises Azerite
     clusters "from the ground on a specific area that is announced",
     guarded by elementals; stage 3 announces a landing site with a
     boss + huge chests, rares + chests/satchels, or mini-bosses
     (moudi guide) - both teams converge on those announcements.
   Exact decision logic (switch lists, aggro radius, player-vs-node
   priority weights, when the AI abandons a node to attack): unverified.
   The readable TrinityCore-based server source contains no enemy-team
   AI at all (section 6), so no server-side targeting rules exist there.

3. HOW FAST IT COLLECTS (numbers)
   Retail-side pace (guides):
   - Targets: Normal 6000, Heroic 9000, Mythic 12000, PvP 12000
     (moudi; cross-check step 1).
   - A run takes about 15-20 minutes (warcraft.wiki.gg) - arithmetic:
     winning Normal needs on average 6000 / 15-20 min = 300-400
     azerite per minute across the island (both factions' gathering
     combined with yours; derived from the two numbers above).
   - Stage triggers (moudi guide, combined totals of BOTH sides;
     one guide only, unverified against client/server data):
       stage 2 (clusters + elementals): Normal ~3000-4000 (33%),
         Heroic ~6000 (33%), Mythic ~12000 (50%);
       stage 3 (boss/event chests): Normal 6000 (50%),
         Heroic 12000 (50%), Mythic 20000 (80%).
   - A per-minute azerite income for the NPC team specifically:
     unverified - no guide publishes it and the server has no AI team.
   Server-side collection math actually implemented in the readable
   8.3.7 server source (TCDEVEmu; how the counter moves):
     - Every creature kill on difficulty 38-45 adds a flat
       +3 azerite to the killer's side:
       int32 baseXP = 3; instance->GiveIslandAzeriteXpGain(...) in
       ps_island_get_xp (npcs_special.cpp); difficulty gate
       DIFFICULTY_NORMAL_ISLAND .. DIFFICULTY_PVP_ISLAND.
     - Spell 260738 "Azerite Residue" (SPELL_AZERITE_RESIDUE) is cast
       on all players when the round starts; each periodic tick adds
       +1 stack, capped at 250 stacks
       (spell_azerite_residue_260738: SetStackAmount(min(+1, 250))).
     - Killing a creature that carries the residue aura pays out its
       current stack count, then resets that target to 1 stack
       (PlayerScript ps_spell_azerite_residue, OnCreatureKill).
     - Killing a PLAYER pays out the victim's stack count (max 250)
       and resets it (same script, OnPVPKill) - this is the "worth
       more the longer you are alive" rule; wiki/guides describe it
       and the server implements it as stacks.
     - GiveIslandAzeriteXpGain sends the azerite packet and adds the
       value to _islandCount[0] (Alliance) or [1] (Horde), then
       updates world states 12930 (Alliance gain) and 13627 (Horde
       gain).
     - Win check in all three implemented scripts:
       GetIslandCount()[0] >= 9000 or [1] >= 9000
       -> IslandComplete(true/false). This server wins at 9000 on
       every difficulty (difficulty-independent); retail uses
       6000/9000/12000/12000 (section 5).
     - Spell 265703 "Azerite Energy" is defined but its cast is
       commented out.
     - Whether the residue tick period is 1 s (aura period value not
       in server data): unverified - so an exact azerite-per-minute
       for THIS server is: unverified (3/kill + stacks/tick are the
       only verifiable rates).

7. PACKETS
   Client -> server:
     CMSG_ISLAND_QUEUE { PackedGuid128 QueueNPCGuid, int32 ActivityID }
       (WowPacketParser V8_0_1_27101; TCDEVEmu IslandOnQueue reads the
       same two fields).
   Server -> client (WPP names / TCDEVEmu local names, same shapes):
     SMSG_ISLANDS_MISSION_NPC / SMSG_ISLAND_OPEN_QUEUE_NPC
       { QueueNPCGuid } - opens the queue NPC dialog.
     SMSG_ISLAND_AZERITE_GAIN / SMSG_ISLAND_AZERITE_XP_GAIN
       { int32 Gain (XpGain), PackedGuid128 PlayerGuid,
         PackedGuid128 SourceGuid, int32 SourceID }
       - TCDEVEmu builds it in GiveIslandAzeriteXpGain with payload
         size 4 + 36 + 36 + 4.
     SMSG_ISLAND_COMPLETE / SMSG_ISLAND_COMPLETED
       { int32 MapID, int32 Winner (0 = Alliance, 1 = Horde),
         uint32 GroupTeamSize, then PlayerModelDisplayInfo per player }
       - TCDEVEmu sends MapID, Winner and the display-info count; the
         display-info block itself is commented out in their Write().
   Client-side event (Blizzard API doc, IslandsInfoDocumentation.lua):
     ISLAND_AZERITE_GAIN payload = { amount, gainedByPlayer,
     factionIndex, gainedBy (WOWGUID), gainedFrom (WOWGUID) }.
   Numeric opcode values for build 35662: unverified (names only in
   the readable sources).

8. TRINITYCORE-STYLE SCENARIO HANDLING (readable 8.3.7 server source)
   Queue entry: HandleIslandQueue (IslandHandler.cpp) takes the
   ActivityID from CMSG_ISLAND_QUEUE and calls
   sLFGMgr->JoinLfg(GetPlayer(), ROLE_DAMAGE, {ActivityID}) - island
   queueing is LFG with the island's activity id, hardcoded to the
   damage role; it also grants quest credits KilledMonsterCredit
   139310 (Alliance) and 139309 (Horde).
   Activity ids per island (lfg_dungeon_template, same as step 1):
     Snowblossom Village 1983/1988/1989/1990 (38/39/40/45)
     Havenswood 1928/1929/1930/1931 (+2025/2055 tagged 153)
     Jorundall 1932/1933/1934/1935 (+2041/2056 tagged 153)
     Verdant Wilds 1724/1743/1746/1763 (+2058 tagged 153)
     Whispering Reef 1735/1740/1749/1908
     Rotting Mire 1723/1744/1745/1764
     Dread Chain 1734/1741/1748/1766
     Crestfall/Molten Cay/Un'gol Ruins/Skittering Hollow: no queue rows
       in the readable SQL (step 1) - unverified for those four.
   Round flow in the three implemented island scripts
   (scenario_verdant_wilds / scenario_ungol_ruins /
   scenario_snowblossom_village):
     - OnPlayerEnter: set faction start point + teleport (server
       implementation data, differs per script), then StartTimer
       (TIMER_TYPE_BATTLEGROUND): verdant 45 s + event at 45 s,
       snowblossom 33 s + event at 33 s, ungol shows 45/45 but
       schedules its start event at 33 s (code as written).
     - EVENT_START_TIMER -> CastIslandAzeriteAura() (260738 on all
       players) -> EVENT_GAME_START every 1 s.
     - On first tick plays conversation 6514 (HORDE_ON_BEGIN);
       enum also defines 7498 (ON_50) and 7487 (ON_80) which are not
       called in these files - their trigger: unverified.
     - Each tick checks both sides against 9000 and calls
       IslandComplete(winner).
     - IslandComplete: remove 260738 from everyone, cast
       245618 "island - complete" on everyone, build
       IslandCompleted{MapID, Winner 0/1, DisplayInfos of the winning
       team's players}, play conversation 7504 when the Horde wins,
       send to the instance.
     - FillInitialWorldStates sends both gain counters; verdant also
       initialises (raw, meanings unverified): 16018=1, 14253=1,
       13004=1, 14065=1, 14246=1, 14063=1, 13321=9, 12889=1,
       12878=1, 12877=1, 3191=20, 3901=18, 14684=6000, 15893=17.
     - Registering: verdant InstanceScript for map 1882, ungol for
       1813 (RegisterInstanceScript), snowblossom via
       InstanceMapScript("scenario_snowblossom_village", 1907)
       (old-style class); aura script spell_azerite_residue_260738
       registered from the ungol file.
   Generic scenario plumbing also present: HandleQueryScenarioPOI
   answers scenario POI queries from sScenarioMgr criteria trees
   (ScenarioHandler.cpp).
   Coverage: only 3 of the 11 rotation islands have scenario scripts in
   this source (1907/1813/1882) - the other 8 islands' server-side
   scenario handling: unverified (absent from the readable source).
   What the server does NOT handle: enemy team spawning, stage 2/3
   events, node/chest rolling (absence as per section 6).
