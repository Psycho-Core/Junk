 Map id 1822. Five encounters: Chopper Redhook, Sergeant Bainbridge,
 Dread Captain Lockwood, Hadal Darkfathom, Viq'goth.
 Companion file to the tactics document. Every number is tagged with the

0. READ THIS FIRST - WHAT THIS FILE CAN AND CANNOT GIVE

  Tags:
    [DB]   a row in a world SQL: a smart_scripts row, a creature_template
           row, or a game object id.
    [SRV]  a line in the 8.3.7 script: siege_of_boralus.h,
           instance_siege_of_boralus.cpp, or one of the four boss files.
    [MDT]  Method Dungeon Tools BattleForAzeroth/SiegeofBoralus.lua:
           name, per-kill force, health, level, clone count.
    [DBM]  DBM-Party-BfA/SiegeofBoralus/*.lua: a stopwatch value.
    [LW]   LittleWigs BfA/SiegeOfBoralus/*.lua: a second stopwatch value.
    [CALC] arithmetic on the numbers above, inputs always given.
    unverified   no readable source carries the value. Never a guess.

  THE HEADLINE, because it shapes the whole file: there is NO public
  creature spawn table for map 1822. I looked in the TrinityCore 11.x
  2024 dungeon file series (the file that does carry this dungeon's
  creature_template_difficulty rows), in the 8.x tree, in the
  AshamaneCore and vSLDB BfA databases, and in a GitHub code search for
  the ids 136483, 129208 and 128650 and for their spawn-row text. Code
  search returns only difficulty and scaling rows: the
  creature rows are not public. So in this file:
    - boss and NPC WORLD POSITIONS are unverified, except the eleven
      script coordinates in section 3, three of which are broken
      placeholders (3.1);
    - pull positions with z are unverified; MDT's layout is reproduced
      in 9.3 as RELATIVE map-space geometry only, because MDT stores
      positions in its own map space and the conversion to world
      coordinates is not in any file I could read;
    - line of sight is unverified;
    - timers, percentages and assignments are fully sourced, because
      they live in the scripts, the DB and the two addons.
  I would rather hand you a short honest section 3 than a page of
  invented coordinates.

1. SOURCES AND THEIR LIMITS

  1.1 The scripts are Psycho-Core-8.3.7_Scripts,
      scripts/KulTiras/SiegeOfBoralus: boss_chopper_redhook.cpp (3.1 KB),
      boss_dread_captain_lockwood.cpp (8.9 KB),
      boss_hadal_darkfathom.cpp (2.1 KB), boss_viqgoth.cpp (9.2 KB),
      instance_siege_of_boralus.cpp, siege_of_boralus.cpp/.h. The world
      file siege_of_boralus.cpp is an empty AddSC - it registers nothing.
  1.2 THERE IS NO SERGEANT BAINBRIDGE SCRIPT. The header gives her
      encounter slot (DATA_SERGEANT_BAINBRIDGE = 2) and the creature id

      Redhook's file even carries the comment "//128650, 128649
      bainbridge" over its struct, but the struct is data 1 and only
      128650 is registered. Everything known about her comes from the
      SmartAI block in 1.3 and the two addons.
  1.3 The DB rows are vSLDB sql/updates/world/Siege of Boralus.sql, 109
      smart_scripts rows over 70 entries. It is the same lineage as the
      King's Rest and Shrine SQL used in steps 08 and 09. It is SmartAI
      for all of the dungeon's trash and - unusually - for three of the
      five bosses as well.
  1.4 MDT BattleForAzeroth/SiegeofBoralus.lua is dungeonIndex 19,
      dungeonTotalCount 319 normal and 383 teeming, 53 enemy records.
      Only its name/force/health/level and its clone counts are used.
  1.5 DBM ships five files (BoralusTrash, Darkfathom, Lockwood,
      Redhook_Bainbridge, ViqGoth); LittleWigs six (Bainbridge,
      Darkfathom, Lockwood, Redhook, Trash, Viqgoth). LittleWigs is on a
      later spell-id generation than BfA for Lockwood: it bars 463182
      Fiery Ricochet and 463185 Mass Bombardment, which do not exist in
      the 8.3.7 scripts or DBM. Treat those two bars as a later-season
      import.
  1.6 No client table was read. Radii, durations and damage are
      unverified unless a script or an addon states them.

2. THE INSTANCE FRAME

  2.1 Map 1822, one area that matters: 9354, the Blood in the Water
      dock. The instance script installs a PlayerScript that runs on
      every player update: if the player's area is 9354 and the player
      is in water, it casts 279893 (screen effect), waits 2.0 s, and
      then casts 276433, an instant kill, if the player is still alive,
      still in water and still carrying 279893. Leaving the water
      removes 279893. The check repeats every 3.0 s [SRV].
      Practical reading: on this core the sea is a hard boundary, and a
      bot that swims to a safe spot drowns. It is the only positional
      rule in the instance that is enforced by code.
  2.2 Five encounters in the header: 1 Chopper Redhook, 2 Sergeant
      Bainbridge, 3 Dread Captain Lockwood, 4 Hadal Darkfathom,
      5 Viq'goth [SRV].
  2.3 Height, from the only coordinates the scripts carry: Lockwood's
      fight is at z 11.06 to 12.58, the deck of the Ashvane ship;
      Viq'goth's arena is at z -3.48, below the waterline; the treasure
      cache after the last boss spawns at z 0.58 to 0.61. Everything
      else has no z in any readable source.

4. BOSS 1 - CHOPPER REDHOOK  (128650, MDT hp 2,819,992, level 122)
==============================================================================

  4.1 SPAWN AND TANK POSITION. Spawn unverified: no spawn row exists in
      any source I could read. TANK: unverified as a coordinate. What
      the script does say is that Gore Crash is cast at the CURRENT
      VICTIM and that On the Hook is cast at a random farthest player,
      which is the opposite of a tank mechanic; see 4.4.

  4.2 PHASES [SRV]. None. There is no HealthBelowPct and no intermission
      in boss_chopper_redhook.cpp. Three events are scheduled once on
      EnterCombat and each re-arms itself.

  4.3 TIMERS, seconds from pull
      ability                 script [SRV]     SmartAI [DB]   LW [LW]
      Gore Crash 257326       1.0, then 15.0   3.0-5.0, then   -
                                                12.0-15.0
      On the Hook 257459      3.0, then 15.0   -               -
      Meat Hook 257348        -                10.0, then      -
                                                20.0-22.0
      Cannon Barrage 272425   6.0, then 20.0   -             11.1 [LW]
      The C++ and the SmartAI disagree because they are two different
      implementations of the same boss. On a core where the creature
      template gives 128650 a ScriptName, the C++ wins; if it gives him
      AIName='SmartAI' and no ScriptName, the DB block runs instead. The
      C++ schedules 257326 Gore Crash while the DB block casts 257326 and
      a separate 257348 Meat Hook that the C++ never uses. DBM's file
      bars neither of them (both are commented out) and only keeps an
      Iron Hook timer at 10.2 s for spell 272662, which is not in either
      implementation - so read the DBM numbers for this boss as stale.
      The addons bar a third spell id for the barrage: DBM's count timer
      is 257540 at 10.1 s with a 60.0 s cooldown, LittleWigs' is 257585
      at 11.1 s. The script casts 272425 every 20.0 s. Three ids, three
      cadences, one fight - see 11.3.

  4.4 ASSIGNED-PLAYER MECHANICS AND EXACT TRIGGERS
      a) GORE CRASH 257326 - THE TANK. Trigger: 1.0 s after pull, then
         every 15.0 s, DoCastVictim. The C++ wraps it in
         if (me->GetDistance(me->GetVictim())), which is always true for
         a non-zero distance, so it is unconditional in practice.
      b) ON THE HOOK 257459 - ONE PLAYER, THE FARTHEST ONE. Trigger:
         3.0 s after pull, then every 15.0 s,
         SelectTarget(SELECT_TARGET_FARTHEST, 0, 100.0f, true). The boss
         strips Heavy Hitter 256867 from himself, applies 257459 to that
         player, adds 100 threat, sets walk off, sets run speed to 0.5
         and chases at PET_FOLLOW_DIST; if he does not already have
         Boiling Rage 257650 he casts it on himself. This is the one
         mechanic in the fight that needs an assignee: the farthest
         player is chosen by geometry, so a bot that stands far away
         volunteers. There is no soak, no kick and no tank swap.
      c) CANNON BARRAGE 272425 - EVERYBODY WITHIN 300 YD. Trigger: 6.0 s
         after pull, then every 20.0 s. GetPlayerListInGrid(300.0f) and
         DoCast on each. 300 yd is larger than any plausible arena, so
         treat it as raid-wide and uninterruptible.

  4.5 SAFE SPOTS, WITH z. Unverified. The script fixes no spot, and the
      water rule in 2.1 makes any 'safe spot' that is in the sea a death
      sentence. The one usable statement is directional: during On the
      Hook the boss walks at 0.5 run speed toward the farthest player,
      so anywhere that is not on that line is safe from the hook.

6. BOSS 3 - DREAD CAPTAIN LOCKWOOD  (129208, MDT hp 3,765,626, level 122)
==============================================================================

  6.1 SPAWN AND TANK POSITION
      Home: (620.000, -245.000, 12.580) o 1.000, map 1822 [SRV].
      Reset teleports her to her home position, so this is both the
      spawn and the post-withdraw return point.
      TANK: unverified as a coordinate. Clear the Deck is cast at the
      top-aggression target inside 30 yd, which is the only
      tank-shaped mechanic in the encounter.

  6.2 PHASES - ONE, AND IT IS DRIVEN BY A 30 SECOND TIMER, NOT HEALTH
      [SRV]. There is no HealthBelowPct anywhere in the file.
      Phase 1: from pull, Shoot 2.5 s, Gut Shot 15 s, Clear the Deck
      20 s, Evasive 17 s.
      At 30 s the Withdraw event fires: she casts 268752 on herself,
      stops attacking, stops casting, goes passive, gains
      UNIT_FLAG_NON_ATTACKABLE, teleports to (662.0, -245.0, 11.06)
      o 3.25, roots herself, cancels the Gut Shot, Withdraw and Shoot
      events, and summons exactly three adds at
      (641.0, -244.0, 12.0) o 3.30: one Ashvane Cannoneer 136549 and two
      Ashvane Deckhand 136483. Cannon Barrage is then scheduled 3.0 s
      later.
      Phase 2 ends when the Cannoneer dies: he casts 268963 (summon of
      Unstable Ordnance 143618), Lockwood teleports back to her home
      position, unroots, loses NON_ATTACKABLE, goes aggressive and
      re-schedules Shoot 1 s, Gut Shot 3 s, Clear the Deck 6 s and
      Withdraw 30 s. So each cycle is 30 s of boss phase and however
      long the add pack lives.
      Note the asymmetry: the CANNONEER's death re-engages her, not the
      Deckhands'. Killing the two deckhands and leaving the cannoneer
      alive parks the boss in phase 2 indefinitely.

         268933, and 3.0 s later the Dread Cannon Bunny 500500 makes every

         there is no fixed safe spot inside that 30 yd circle - the

8. BOSS 5 - VIQ'GOTH  (128652, MDT hp 19,212,375, level 122)
==============================================================================

  8.1 SPAWN AND TANK POSITION: unverified. The only coordinate is the
      swim destination in 3.2, (84.71, -268.0, -3.48), used after the
      third cannon. The boss starts passive, NON_ATTACKABLE and swimming
      (SetSwim(true) in reset).

  8.2 HOW THE FIGHT STARTS [SRV]. Viq'goth cannot be engaged directly.
      A Demolishing Terror 137614's EnterCombat looks for Viq'goth
      within 100 yd, removes her NON_ATTACKABLE flag and calls
      DoZoneInCombat(nullptr, 250.0f). The same function checks a
      Gripping Terror 137405 and, if that terror is 45 to 50 yd from
      the Demolishing Terror that is entering combat, disengages it.
      So the arena is entered through the two tentacle adds, and the
      45-50 yd band is the only distance the script ever tests.

  8.3 PHASES - NONE IN THIS FILE, BUT THE KILL IS SCRIPTED [SRV]
      Putrid Waters is the only live boss event. There is no health
      gate. The end of the encounter is the cannon 137123: its gossip
      handler casts 269416 and 269420 on Viq'goth, then computes
      pct = cannon_count * 33 / 100, sets health to
      MaxHealth - MaxHealth * pct, and only AFTER that increments
      cannon_count. Read the order carefully, because it decides what
      each click does: click 1 runs with count 0 and sets her to 100%,
      click 2 runs with count 1 and sets 67%, click 3 runs with count 2
      and sets 34%. What ends the fight is the next test, not the
      health: when cannon_count reaches 3 the handler calls her
      JustDied, sets the boss state to DONE, makes her non-attackable
      and unselectable, clears her auras, moves her to
      (84.71, -268.0, -3.48) at 1.5 swim speed, despawns the terrors
      and the cannon, grants kill credit 2100, despawns her after 20 s
      and starts the Jaina outro (3.3).
      So the encounter ends with a third of her health still on the
      bar. The last third is scripted away, not killed, and the first
      click does no damage at all. cannon_count is also never
      initialised (11.7), so a fresh object starts from an
      indeterminate count and the percentages above assume it starts
      at 0.

  8.5 ASSIGNED-PLAYER MECHANICS AND EXACT TRIGGERS
      a) PUTRID WATERS 275014 - EVERY PLAYER WITHIN 150 YD, every 20.0 s

         not implement either.
      b) THE CANNON 137123 IS THE ASSIGNMENT. One player clicks it three
         times over the fight. The clicks set her health to 100%, 67%
         and 34% in that order, and the third click is the one that
         calls JustDied (8.3, 11.6); the first click does no damage.
         Any bot order needs a designated clicker or the encounter
         cannot finish.
      c) DEMOLISHING TERROR 137614 - two events: Slam 269266, 1.0 s then
         every 15.0 s, gated on a random target inside 35 yd but cast as
         DoCastAOE; and Hullcracker 270590, armed in reset() at 1.0 s
         then every 17.0 s, but only cast if the add is in combat.
      d) GRIPPING TERROR 137405 has NO AI CLASS in this repository. It is
         referenced by id in the other scripts and has no file of its
         own, so its behaviour is unverified.
      e) SOAK LISTS, KICK ORDER, TANK SWAPS: none anywhere in the file.

  8.6 SAFE SPOTS, WITH z. Unverified beyond two facts: the arena floor is
      below the waterline (the boss is made to swim, and the post-fight

  9.3 THE PULL LAYOUT, AND WHY IT IS NOT IN THIS FILE AS COORDINATES
      MDT stores every clone in its own map space and this file has no
      z at all. For step 09 the spawn rows came from a TrinityCore 11.x
      world file; for map 1822 no such file exists, so the honest
      position of every pull is unverified.
      What MDT does give, and what is usable without a conversion: the
      ORDER and the SPACING of the four wings. Taking MDT's five boss
      clones as the reference points, the dungeon runs:
        Redhook    (490.4, -158.5)   first wing, with Bainbridge
                                     (488.4, -156.0) in the same yard
        Lockwood   (445.6, -332.7)   180 MDT units from Redhook
        Hadal      (394.1, -451.7)   130 MDT units from Lockwood
        Viq'goth   (433.8, -522.3)   81 MDT units from Hadal, in the
                                     flooded pit
      Those are MDT map units, not yards, and I am not going to pretend
      otherwise. What they do establish is the shape: three wings in a
      line south-west away from the docks, then the last arena below.
      The counts per enemy in 9.1 are the pull sizes to plan for.
